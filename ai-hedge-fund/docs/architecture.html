MJ Research — System Architecture

Local-first AI research and portfolio workstation. Five diagrams that together describe how a ticker flows from browser click to AI committee thesis and back, plus how the whole stack is also exposed as an MCP server.

1 · System overview

Three client surfaces (browser, CLI, Claude Desktop), one core stack. Everything local-first: Ollama runs the LLM; SQLite is the portfolio book; external APIs are called only when keys are configured.

AI / LLM path Data layer Core service External / optional
Clients don't talk to core services directly — everything goes through FastAPI or FastMCP. This keeps the research graph, backtester, optimizer, and screeners behind stable interfaces that both the web UI and Claude Desktop can use identically.

2 · Multi-provider data layer

A single ProviderRegistry routes a DataCategory request through an ordered chain of providers, handling caching, rate limits, and graceful fallback. JSON config is authoritative for priority.

Registry · cache · limiter Primary for a category Secondary / fallback External API / package
  • DataCategory has 17 values (PRICE, FUNDAMENTALS, TECHNICALS, MACRO, NEWS, ESG, INSIDER, INSTITUTIONAL, EARNINGS, ANALYST, SENTIMENT, SECTOR_PERFORMANCE, FAMA_FRENCH, OPTIONS, SEC_FILINGS, CONGRESSIONAL, PEERS).
  • Priority is read from config/providers.json and overrides the class-level default — change it there, not in code.
  • Providers self-register via BaseProvider.__init_subclass__; adding a new one is two files (providers/foo.py + config entry).

3 · AI research graph (fan-out → reduce)

Committee mode fans the same market snapshot out to N named investor personas in parallel, then reduces their JSON analyses into a single Portfolio Manager synthesis. Execution model: parallel_fanout_then_reduce.

AI node (Ollama) Data / output node External call
Before parallelization, a 4-persona committee was 4 sequential LLM calls plus synthesis — roughly 60–80s on llama3.2. With asyncio.gather fan-out the personas run concurrently: measured 24.3s wall-clock for AAPL with 4 successful persona analyses and a successful PM synthesis. GET /api/research/graph returns this exact topology as JSON for UI rendering.

4 · Request lifecycle — "research a ticker with committee"

Sequence diagram of a single research call, from browser click through to rendered committee cards and Signal Intelligence callouts.

AI / LLM path Standard call
The UI also fires GET /api/data/analyst/{t} and GET /api/data/sentiment/{t} in parallel so the Signal Intelligence panel can show non-consensus callouts (contrarian to analysts, buying pessimism, unusual buzz) as soon as the AI thesis returns — it's purely frontend logic from the union of those responses.

5 · MCP integration — Claude Desktop / Cursor

The same core services are wrapped as MCP tools in hedge_fund/mcp/server.py and served via the hedge-fund-mcp script entrypoint. Claude Desktop spawns it over stdio.

AI / MCP surface Data / quant tool
Same core, two front doors. Anything the Web UI can do, Claude Desktop can do by calling these tools — and vice versa. The MCP server uses FastMCP's @mcp.tool() decorator, so adding a new tool is literally one function.
